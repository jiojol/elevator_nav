# 场景切换的残留节点修正 · 2026-10-28

故障现场：箱体物理会话已经写出 `session_closed`，启动管理进程已不在，但其 roscore、roslaunch 和规划/控制节点仍然存活。
新楼梯入口可以取得运行锁，却在同一个回环 master 发现旧节点而退出；不是锁文件过期，也不是楼梯导航算法报错。

修正：

- 仅清理已验证属于本工作区、同一回环 master、并有结束记录的进程；同时核对参数、进程身份及日志目录。陌生活动节点不自动清理。
- Linux 父进程死亡信号将每个启动器生命周期绑定到管理进程。管理进程被强制杀死时，ROS 启动器与物理进程也收到中断。
- 管理进程处理 SIGTERM/SIGHUP 并执行 finally 清理，清理期间避免第二次中断打断清理。
- 物理结果记录使用配置的 master URI，避免 master 先退出后又因查询 URI 失败而丢失结果。

验证：

1. 3 项进程生命周期单元检查通过，覆盖 SIGTERM 清理、父进程被杀后的子进程中断，以及拒绝恢复无关节点。
2. 在实际楼梯本机环境中强制杀死管理进程，等待所有已登记节点及 master 退出，物理结果仍保存。
3. 构造旧版“已结束输出 + 无管理进程 + 残留 ROS 启动器”的同类故障，新入口自动清理后楼梯交互页面就绪。
4. 点击结束后管理进程正常返回，所有本次节点和 master 消失。

[集成检查记录](lifecycle_fix/verification.json)。测试只检查启动、结束及异常清理，没有发布导航目标，不能把它当作楼梯行走验收。没有远端连接或机器狗部署。
